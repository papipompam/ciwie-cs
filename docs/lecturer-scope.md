# ขอบเขตระบบสำหรับอาจารย์

อาจารย์สามารถติดตามการสมัครและเอกสารของนักศึกษาทั้งหมด ช่วยออกและส่งเอกสาร ตรวจแบบตอบรับ จัดการตารางนิเทศ บันทึกผลนิเทศ เก็บ Requirement จากสถานประกอบการ และประเมินนักศึกษากับสถานประกอบการในแต่ละรอบการนิเทศ

อาจารย์มีสิทธิ์แก้ไขงานวิชาการและงานนิเทศของอาจารย์คนอื่นได้ เพื่อรองรับเหตุการณ์ที่ไม่คาดคิดและการมอบหมายผู้ไปนิเทศแทน ทุกการเปลี่ยนแปลงต้องมีประวัติตรวจสอบย้อนหลัง

## 1. บัญชีและข้อมูลส่วนตัว

อาจารย์สามารถ:

- เข้าสู่ระบบและออกจากระบบ
- ดูข้อมูลส่วนตัว
- แก้ไขหมายเลขโทรศัพท์ อีเมล หรือข้อมูลติดต่อที่ได้รับอนุญาต
- เปลี่ยนรหัสผ่าน
- ดูสถานะบัญชี
- ดูงานที่ได้รับมอบหมาย
- ดูการแจ้งเตือนของตนเอง

ข้อมูลหลัก เช่น รหัสอาจารย์ ชื่อ และบทบาทบัญชี แก้ไขโดยผู้ดูแลระบบ

## 2. ดูและแก้ไขข้อมูลนักศึกษา

อาจารย์สามารถ:

- นำเข้ารายชื่อนักศึกษาจากไฟล์ CSV หรือ Excel (`.xlsx`)
- ดูตัวอย่างข้อมูลและรายการที่ผิดพลาดก่อนยืนยันการนำเข้า
- ดูรายชื่อนักศึกษาสาขาวิทยาการคอมพิวเตอร์ทั้งหมด
- ค้นหาด้วยรหัสนักศึกษา ชื่อ หรือนามสกุล
- กรองตามปีที่เข้าศึกษา สถานประกอบการ หรือสถานะ
- ดูและแก้ไขข้อมูลพื้นฐานของนักศึกษา
- แก้ไขชื่อและนามสกุล
- แก้ไขข้อมูลการศึกษา
- แก้ไขหมายเลขโทรศัพท์ อีเมล และที่อยู่
- แก้ไขข้อมูลสถานที่ฝึกงาน
- แก้ไขข้อมูลที่นักศึกษาบันทึกผิด
- ดูสถานประกอบการที่นักศึกษาสมัคร
- ดูสถานะและประวัติการสมัคร
- ดูหนังสือและแบบตอบรับที่เกี่ยวข้อง
- ดูสถานที่ฝึกงานที่ได้รับการยืนยัน
- ดูประวัติการนิเทศ
- ดูประวัติการเปลี่ยนแปลงข้อมูลนักศึกษา

การนำเข้าต้องตรวจสอบรหัสนักศึกษาซ้ำ ช่องข้อมูลที่จำเป็น และรูปแบบข้อมูลก่อนบันทึก ระบบต้องไม่เขียนทับข้อมูลเดิมโดยอัตโนมัติเมื่อพบข้อมูลขัดแย้ง และต้องเก็บผู้ดำเนินการ วันเวลา ชื่อไฟล์ และผลการนำเข้าไว้ตรวจสอบย้อนหลัง การนำเข้าโดยอาจารย์ไม่ให้สิทธิ์จัดการรหัสเปิดใช้งาน รหัสผ่าน หรือบทบาทบัญชี

อาจารย์ไม่สามารถ:

- เปลี่ยนบทบาทบัญชีผู้ใช้
- ดูหรือแก้ไขรหัสผ่านของนักศึกษา
- ลบบัญชีผู้ใช้ถาวร
- จัดการรหัสเปิดใช้งานบัญชี

การแก้ไขข้อมูลสำคัญต้องเก็บค่าก่อนแก้ไข ค่าใหม่ ผู้แก้ไข วันเวลา และเหตุผล

## 3. ดูข้อมูลสถานประกอบการ

อาจารย์สามารถ:

- ดูสถานประกอบการที่นักศึกษาบันทึกทั้งหมด
- ค้นหาด้วยชื่อหรือจังหวัด
- ดูที่อยู่และข้อมูลติดต่อ
- ดูรายชื่อนักศึกษาที่สมัครแต่ละแห่ง
- ดูรายชื่อนักศึกษาที่ได้รับการตอบรับ
- ดูเอกสารที่เกี่ยวข้อง
- ดูประวัติการนิเทศ
- ดู Requirement ที่เคยเก็บ
- ดูผลประเมินสถานประกอบการแยกตามรอบการนิเทศ
- แจ้งหรือแก้ไขข้อมูลสถานประกอบการที่ผิดตามสิทธิ์

การรวม ลบ หรือเปลี่ยนข้อมูลหลักของสถานประกอบการต้องมีประวัติการแก้ไขและเป็นไปตามสิทธิ์ที่ระบบกำหนด

## 4. ติดตามและจัดการสถานะการสมัคร

อาจารย์สามารถ:

- ดูประวัติการสมัครของนักศึกษาทั้งหมด
- ดูตำแหน่งและวันที่สมัคร
- กรองตามนักศึกษา สถานประกอบการ หรือสถานะ
- เปลี่ยนสถานะการสมัคร
- แก้ไขสถานะที่นักศึกษาบันทึกผิด
- เพิ่มหมายเหตุ
- ดูหลักฐานประกอบ
- ดูผู้ดำเนินการและเวลาที่เปลี่ยนสถานะ

สถานะการสมัครประกอบด้วย:

1. `SUBMITTED` — ยื่นสมัครแล้ว
2. `WAITING_RESPONSE` — รอการตอบกลับ
3. `INTERVIEW_PENDING` — รอสัมภาษณ์
4. `PRELIMINARY_ACCEPTED` — สถานประกอบการแจ้งตอบรับเบื้องต้น แต่ยังไม่ถือว่าเป็นสถานที่ฝึกงานที่ยืนยันแล้ว
5. `REJECTED` — สถานประกอบการปฏิเสธ
6. `CANCELLED` — ยกเลิกการสมัคร

ทุกการแก้ไขต้องเก็บสถานะเดิม สถานะใหม่ ผู้ดำเนินการ วันเวลา และเหตุผลหรือหมายเหตุ

## 5. การออกเอกสาร

อาจารย์สามารถช่วยดำเนินการออกเอกสารเช่นเดียวกับผู้ดูแลระบบ โดยสามารถ:

- ดูคำขอออกเอกสาร
- ตรวจสอบข้อมูลนักศึกษาและสถานประกอบการ
- ตรวจสอบผู้ติดต่อของสถานประกอบการ
- ดูชุดเอกสารที่จัดกลุ่มไว้
- ตรวจสอบรายชื่อนักศึกษาในชุด
- บันทึกเลขที่หนังสือ
- บันทึกวันที่ออกหนังสือ
- จัดทำเอกสารภายนอกระบบ
- อัปโหลดหนังสือฉบับสมบูรณ์
- อัปโหลดแบบตอบรับเปล่า
- ดูตัวอย่างและดาวน์โหลดไฟล์
- แก้ไขไฟล์ก่อนส่ง
- ดูประวัติไฟล์และฉบับแก้ไข

สถานะคำขอจัดทำเอกสารประกอบด้วย:

1. `REQUESTED` — นักศึกษาส่งคำขอแล้ว
2. `IN_PROGRESS` — อยู่ระหว่างตรวจสอบและจัดทำเอกสาร
3. `READY_TO_SEND` — เอกสารผ่านการตรวจสอบและพร้อมนำส่ง

คำขอออกเอกสารต้องเป็นข้อมูลรายนักศึกษาและแยกจากชุดเอกสารหลายคน การรวมคำขอหมายถึงการเชื่อมคำขอแต่ละรายการเข้ากับชุดเอกสาร ไม่ใช่การรวม record หรือประวัติคำขอเข้าด้วยกัน

หลักการจัดกลุ่มเอกสาร:

- นักศึกษาที่ไปสถานประกอบการเดียวกันในรอบสหกิจเดียวกันใช้เอกสารชุดเดียว
- สถานประกอบการเดียวกันแต่คนละสาขาหรือสถานที่ปฏิบัติงานสามารถแยกชุดได้
- เมื่อส่งเอกสารแล้ว ต้องไม่แทนที่ไฟล์เดิมโดยไม่มีประวัติฉบับแก้ไข
- ชุดเอกสารต้องมีสมาชิกเชื่อมกลับไปยังคำขอและนักศึกษาแต่ละคน
- เลขที่หนังสือ ไฟล์ แบบตอบรับ และสถานะการส่งผูกกับชุดเอกสาร ส่วนสถานะและประวัติคำขอคงอยู่รายคน
- แบบตอบรับผูกกับชุดเอกสาร นักศึกษาคนใดคนหนึ่งในชุดสามารถอัปโหลดและกรอกผล `ACCEPTED` หรือ `DECLINED` ให้สมาชิกแต่ละคนเป็นฉบับร่างได้ แต่ Lecturer หรือ Admin ต้องตรวจและยืนยันผลแยกรายคนก่อนสร้างสถานที่ฝึกงาน

ในระบบรุ่นแรก เอกสารจัดทำแบบ Manual แล้วอัปโหลดเข้าสู่ระบบ โดยยังไม่สร้าง PDF อัตโนมัติ

## 6. การส่งเอกสาร

ระบบกำหนดให้นักศึกษาเป็นผู้ส่งเอกสารโดยค่าเริ่มต้น แต่อาจารย์สามารถรับหน้าที่ส่งแทนได้

เมื่ออาจารย์เป็นผู้ส่ง สามารถ:

- เปลี่ยนผู้รับผิดชอบการส่งเป็นตนเอง
- ดาวน์โหลดหนังสือและแบบตอบรับ
- ระบุว่าส่งเอกสารแล้ว
- บันทึกวันที่ส่ง
- บันทึกช่องทางการส่ง
- บันทึกผู้รับเอกสาร ถ้าทราบ
- เพิ่มหมายเหตุ
- แนบหลักฐานการส่ง ถ้ามี

สถานะการนำส่งเอกสารประกอบด้วย:

1. `SENT` — ส่งให้สถานประกอบการแล้ว
2. `WAITING_RESPONSE` — รอแบบตอบรับ
3. `RESPONSE_RECEIVED` — ได้รับแบบตอบรับแล้ว

นักศึกษาต้องสามารถดูสถานะที่อาจารย์บันทึกได้

## 7. ตรวจสอบแบบตอบรับ

เมื่อนักศึกษาอัปโหลดแบบตอบรับ อาจารย์สามารถ:

- ดูและดาวน์โหลดไฟล์
- ตรวจสอบสถานประกอบการ
- ตรวจสอบรายชื่อนักศึกษา
- ตรวจสอบผลว่ายินดีรับหรือขัดข้องไม่สามารถรับได้
- ตรวจสอบจำนวนที่สถานประกอบการรับ
- ตรวจสอบเงื่อนไขเพิ่มเติม
- แก้ไขข้อมูลที่บันทึกผิด
- เพิ่มหมายเหตุ
- ตรวจผลฉบับร่างแยกรายคน
- แก้เฉพาะผลรายคนที่ผิด
- ยืนยันสมาชิกทั้งหมดในชุดด้วยคำสั่งเดียว
- ส่งกลับให้นักศึกษาแก้ไขพร้อมหมายเหตุ

สถานะการตรวจแบบตอบรับประกอบด้วย:

1. `DRAFT` — นักศึกษาผู้อัปโหลดยังกรอกข้อมูลหรือผลรายคนไม่ครบ
2. `PENDING_REVIEW` — นักศึกษาส่งให้ตรวจแล้ว
3. `CONFIRMED` — Lecturer หรือ Admin ยืนยันผลสมาชิกทั้งชุดแล้ว

เมื่ออยู่ใน `PENDING_REVIEW` นักศึกษาแก้ไขไม่ได้ อาจารย์สามารถแก้เฉพาะรายการที่ผิดหรือส่งกลับเป็น `DRAFT` การยืนยันทั้งชุดต้องบันทึกผู้ยืนยัน เวลา และผลแยกเป็นรายนักศึกษา

เมื่อยืนยันแล้ว:

- หากยินดีรับ ให้ยืนยันเป็นสถานที่ฝึกงาน
- หากไม่สามารถรับได้ ให้ปิดกระบวนการของสถานประกอบการนั้น
- นักศึกษามีสถานที่ฝึกงานที่ยืนยันแล้วได้เพียงแห่งเดียวต่อรอบสหกิจศึกษา
- นักศึกษาที่ได้รับการยืนยันแล้วมีสถานะสถานที่ฝึกงานเป็น `CONFIRMED_PLACEMENT` ซึ่งแยกจาก `PRELIMINARY_ACCEPTED` ในสถานะการสมัคร

การยืนยันแบบตอบรับและการสร้างสถานที่ฝึกงานต้องอยู่ใน database transaction เดียวกัน ฐานข้อมูลต้องบังคับ unique constraint ต่อ `(นักศึกษา, รอบสหกิจ)` สำหรับสถานที่ฝึกงานที่ยืนยันแล้ว หากมีผู้ยืนยันพร้อมกันให้สำเร็จได้เพียงรายการเดียว

## 8. ดูและจัดการตารางนิเทศ

นักศึกษาทุกคนต้องได้รับการนิเทศสหกิจศึกษา 2 ครั้ง โดยผู้ดูแลระบบเป็นผู้วางแผนและกำหนดวันนิเทศเอง

- การนิเทศครั้งที่ 1 ดำเนินการภายในสัปดาห์ที่ 4–6 ของการปฏิบัติงาน
- การนิเทศครั้งที่ 2 ดำเนินการก่อนสิ้นสุดการปฏิบัติงาน

ผู้ดูแลระบบเป็นผู้รับผิดชอบจัดทำแผนเริ่มต้น แต่อาจารย์ทุกคนสามารถสร้างและแก้ไขตารางภายหลังได้ โดยทุกการเปลี่ยนแปลงต้องมี Audit Log

หนึ่งรายการนิเทศหมายถึง หนึ่งรอบการนิเทศ + หนึ่งวัน + หนึ่งช่วงเวลา + หนึ่งสถานประกอบการ โดยหนึ่งรายการมีนักศึกษาหลายคนและอาจารย์หลายคนได้ สถานะนิเทศผูกกับรายการนี้ ส่วนผลที่แตกต่างกันของนักศึกษาให้บันทึกแยกรายคนภายในรายการ

อาจารย์สามารถ:

- ดูตารางนิเทศทั้งหมด
- ดูตารางที่ตนเองได้รับมอบหมาย
- ดูตารางแยกตามการนิเทศครั้งที่ 1 และครั้งที่ 2
- ดูตารางแยกตามวัน ช่วงเช้า และช่วงบ่าย
- ดูว่าแต่ละวันอาจารย์แต่ละคนไปสถานประกอบการใด
- ดูว่าแต่ละสถานประกอบการมีอาจารย์คนใดไปบ้าง
- สร้างตารางนิเทศ
- แก้ไขวันและเวลา
- แก้ไขช่วงเช้าหรือช่วงบ่าย
- แก้ไขสถานประกอบการ
- แก้ไขนักศึกษาที่อยู่ในตาราง
- เปลี่ยนอาจารย์ผู้รับผิดชอบ
- เพิ่มอาจารย์มากกว่าหนึ่งคนในรายการนิเทศเดียวกัน
- เลื่อนหรือยกเลิกกำหนดการ
- แก้ไขตารางนิเทศของอาจารย์คนอื่น
- มอบหมายให้อาจารย์ท่านอื่นไปนิเทศแทน
- เพิ่มเหตุผลในการเปลี่ยนแปลง
- ดูประวัติการเปลี่ยนตาราง
- ดูข้อมูลติดต่อของนักศึกษาและสถานประกอบการ
- ดูหมายเหตุสำหรับเตรียมการ
- กดรับทราบตาราง

ก่อนบันทึกการเปลี่ยนแปลง ระบบต้องตรวจสอบ:

- ตารางเวลาของอาจารย์คนใหม่ชนกับงานอื่นหรือไม่
- นักศึกษามีตารางนิเทศซ้ำหรือไม่
- กำหนดการเดิมผ่านไปแล้วหรือไม่
- ตารางมีผลนิเทศบันทึกไว้แล้วหรือไม่

เมื่อเปลี่ยนอาจารย์หรือกำหนดการ ระบบต้องแจ้งนักศึกษา อาจารย์เดิม และอาจารย์คนใหม่

สถานะการนิเทศแต่ละครั้งประกอบด้วย:

- จัดตารางแล้ว
- นิเทศเสร็จแล้ว
- เลื่อน
- ยกเลิก

“ยังไม่ได้จัดตาราง” เป็น supervision coverage ที่ระบบคำนวณจากนักศึกษาที่มีสถานที่ฝึกงานยืนยันแล้วแต่ยังไม่มีรายการนิเทศที่กำลังใช้งานในรอบนั้น ไม่ใช่สถานะของรายการนิเทศ

## 9. บันทึกและแก้ไขผลการนิเทศ

อาจารย์สามารถ:

- ดูผลนิเทศทั้งหมด
- บันทึกผลนิเทศของตนเอง
- บันทึกผลนิเทศแทนอาจารย์ผู้รับผิดชอบ
- แก้ไขผลนิเทศของอาจารย์คนอื่น
- เพิ่มหรือแก้ไขบันทึกการนิเทศ
- เปลี่ยนสถานะว่านิเทศแล้วหรือยัง
- กำหนดสถานะว่านิเทศเสร็จแล้วหลังดำเนินการเสร็จ
- ดูประวัติการแก้ไขผล

ข้อมูลผลการนิเทศประกอบด้วย:

- วันที่นิเทศจริง
- รูปแบบการนิเทศ เช่น ลงพื้นที่หรือออนไลน์
- ผู้เข้าร่วมจากสถานประกอบการ
- สภาพการทำงานของนักศึกษา
- งานที่นักศึกษาได้รับมอบหมาย
- ความก้าวหน้าของงาน
- ปัญหาที่พบ
- ข้อเสนอแนะให้นักศึกษา
- ข้อเสนอแนะให้สถานประกอบการ
- แนวทางติดตามครั้งถัดไป
- หมายเหตุภายใน
- สถานะว่านิเทศแล้ว

สถานะต้องบันทึกแยกตามรายการนิเทศในแต่ละรอบ แต่ละวัน และแต่ละสถานประกอบการ หากวันเดียวกันมีหลายสถานประกอบการ อาจารย์ต้องกำหนดสถานะของแต่ละรายการแยกกัน

ระบบต้องเก็บ:

- ผู้บันทึกผลเดิม
- ผู้แก้ไขล่าสุด
- อาจารย์ที่ได้รับมอบหมายในตาราง
- วันและเวลาที่แก้ไข
- ข้อมูลก่อนและหลังแก้ไข
- เหตุผลในการแก้ไข

ข้อมูลเดิมต้องไม่ถูกแทนที่โดยไม่มีประวัติย้อนหลัง

## 10. หมายเหตุภายใน

อาจารย์สามารถ:

- ดูหมายเหตุภายในของอาจารย์ทุกคน
- ดูชื่อผู้เขียนหมายเหตุ
- ดูวันที่สร้างและวันที่แก้ไข
- เพิ่มหมายเหตุของตนเอง
- แก้ไขหรือลบเฉพาะหมายเหตุที่ตนเองสร้าง

หมายเหตุต้องเก็บเป็นรายการแยกตามผู้เขียน ไม่ใช้ช่องข้อความร่วมที่อาจารย์หลายคนสามารถเขียนทับกัน

## 11. บันทึก Requirement จากสถานประกอบการ

Requirement ต้องแยกจากหมายเหตุการนิเทศ เพื่อให้นำไปค้นหาและสรุปรายงานได้

อาจารย์สามารถบันทึก:

- สถานประกอบการ
- วันที่เก็บข้อมูล
- ประเภทงานที่สถานประกอบการต้องการ
- ความรู้ที่ต้องการ
- ทักษะทางเทคนิค
- เทคโนโลยีหรือเครื่องมือที่ใช้
- ทักษะภาษา
- ทักษะการสื่อสาร
- ทักษะการทำงานร่วมกัน
- คุณสมบัติเฉพาะ
- ปัญหาที่พบจากนักศึกษาฝึกงาน
- ข้อเสนอแนะต่อการเตรียมนักศึกษา

Requirement ควรบันทึกเป็นรายการย่อยเพื่อให้ค้นหาและสรุปได้ ตัวอย่าง:

```text
ประเภท: ทักษะทางเทคนิค
Requirement: ต้องการให้นักศึกษามีพื้นฐาน SQL
```

```text
ประเภท: การเตรียมนักศึกษา
Requirement: ควรฝึกการนำเสนอและการสื่อสารก่อนออกฝึกงาน
```

## 12. การประเมินนักศึกษา

อาจารย์สามารถประเมินนักศึกษาแยกในการนิเทศครั้งที่ 1 และครั้งที่ 2 โดยผลประเมินต้องผูกกับนักศึกษาและรายการนิเทศที่เกิดขึ้นจริง ไม่ใช้ผลรวมรายการเดียวครอบคลุมทั้งสองรอบ

อาจารย์สามารถ:

- บันทึกแบบประเมินนักศึกษาที่อยู่ในรายการนิเทศ
- บันทึกเป็นฉบับร่างและส่งผลประเมินเมื่อกรอกข้อมูลที่จำเป็นครบ
- ดูผลประเมินนักศึกษาทั้งหมดแยกตามรอบการนิเทศ
- แก้ผลประเมินของตนเอง
- แก้ผลประเมินของอาจารย์คนอื่นได้ โดยต้องระบุเหตุผล
- ดูผู้ประเมิน ผู้แก้ไขล่าสุด และประวัติการเปลี่ยนแปลง

ผลประเมินหนึ่งรายการต้องประกอบด้วย:

- รายการนิเทศและรอบการนิเทศ
- นักศึกษาที่รับการประเมิน
- แบบประเมินและฉบับของแบบประเมินที่ใช้
- คำตอบหรือคะแนนแยกตามหัวข้อ
- ข้อคิดเห็นและข้อเสนอแนะ
- สถานะ `DRAFT` หรือ `SUBMITTED`
- ผู้ประเมิน วันที่ประเมิน ผู้แก้ไขล่าสุด และวันเวลาแก้ไข

หัวข้อ เกณฑ์ คะแนน น้ำหนัก และเงื่อนไขผ่านหรือไม่ผ่านให้กำหนดในแบบประเมินที่มีเลขฉบับ ระบบต้องเก็บแบบประเมินฉบับเดิมไว้กับผลที่ส่งแล้ว เพื่อไม่ให้การแก้แบบประเมินภายหลังกระทบผลย้อนหลัง

ผลที่ `SUBMITTED` ต้องเก็บเลขฉบับและ snapshot ของหัวข้อ ประเภทคำตอบ คะแนนเต็ม น้ำหนัก และคำตอบที่ใช้จริง การแก้แบบประเมินภายหลังต้องสร้างฉบับใหม่และห้ามเปลี่ยนความหมายหรือผลรวมของการประเมินเดิม

## 13. การประเมินสถานประกอบการ

อาจารย์สามารถประเมินสถานประกอบการแยกในการนิเทศครั้งที่ 1 และครั้งที่ 2 โดยผลประเมินต้องผูกกับสถานประกอบการและรายการนิเทศที่เกิดขึ้นจริง

อาจารย์สามารถ:

- บันทึกแบบประเมินสถานประกอบการในรายการนิเทศ
- บันทึกเป็นฉบับร่างและส่งผลประเมินเมื่อกรอกข้อมูลที่จำเป็นครบ
- ดูผลประเมินสถานประกอบการทั้งหมดแยกตามรอบการนิเทศ
- แก้ผลประเมินของตนเอง
- แก้ผลประเมินของอาจารย์คนอื่นได้ โดยต้องระบุเหตุผล
- ดูผู้ประเมิน ผู้แก้ไขล่าสุด และประวัติการเปลี่ยนแปลง

ผลประเมินหนึ่งรายการต้องประกอบด้วย:

- รายการนิเทศ รอบการนิเทศ และสถานประกอบการ
- แบบประเมินและฉบับของแบบประเมินที่ใช้

- ระดับความเหมาะสม ข้อคิดเห็น และข้อเสนอแนะ

หัวข้อ เกณฑ์ คะแนน และระดับความเหมาะสมให้กำหนดในแบบประเมินที่มีเลขฉบับ ระบบต้องเก็บแบบประเมินฉบับเดิมไว้กับผลที่ส่งแล้ว เพื่อไม่ให้การแก้แบบประเมินภายหลังกระทบผลย้อนหลัง

ผลที่ `SUBMITTED` ต้องเก็บเลขฉบับและ snapshot ของหัวข้อ ประเภทคำตอบ คะแนนเต็ม น้ำหนัก และคำตอบที่ใช้จริง การแก้แบบประเมินภายหลังต้องสร้างฉบับใหม่และห้ามเปลี่ยนความหมายหรือผลรวมของการประเมินเดิม

## 14. ดูประวัติและรายงาน

อาจารย์สามารถดู:

- ประวัติการสมัครของนักศึกษา
- ประวัติการออกและส่งเอกสาร
- แบบตอบรับจากสถานประกอบการ
- นักศึกษาที่ได้รับการยืนยันสถานที่ฝึกงาน
- ตารางนิเทศทั้งหมด
- ประวัติการนิเทศย้อนหลัง
- Requirement ที่อาจารย์ทุกคนบันทึก
- ผลประเมินนักศึกษาและสถานประกอบการแยกตามรอบการนิเทศ
- สรุปทักษะหรือเทคโนโลยีที่สถานประกอบการต้องการ
- ส่งออกรายชื่อนักศึกษาและข้อมูลการฝึกงานเป็นไฟล์ CSV หรือ Excel (`.xlsx`)

การส่งออกต้องใช้ตัวกรองที่ผู้ใช้เลือกได้ เช่น รอบสหกิจ ปีการศึกษา ภาคเรียน สถานประกอบการ จังหวัด และสถานะ และส่งออกเฉพาะข้อมูลการฝึกงานกับรายชื่อนักศึกษาที่อาจารย์มีสิทธิ์เข้าถึง รายงานส่วนกลางประเภทอื่นยังเป็นสิทธิ์ของผู้ดูแลระบบ เว้นแต่มีการกำหนดสิทธิ์เพิ่มเติม

## 15. การแจ้งเตือน

อาจารย์ควรได้รับการแจ้งเตือนเมื่อ:

- มีคำขอให้ออกเอกสาร
- ได้รับมอบหมายให้ส่งเอกสาร
- นักศึกษาอัปโหลดแบบตอบรับ
- ได้รับมอบหมายให้เป็นอาจารย์นิเทศ
- ตารางนิเทศถูกเปลี่ยนหรือยกเลิก
- ถูกเปลี่ยนออกจากตารางนิเทศ
- ใกล้ถึงวันนิเทศ
- ยังไม่ได้บันทึกผลนิเทศ
- ยังไม่ได้บันทึก Requirement
- ยังไม่ได้ส่งผลประเมินนักศึกษาหรือสถานประกอบการในรอบที่รับผิดชอบ

การแจ้งเตือนภายในระบบเป็นช่องทางหลัก ส่วนอีเมลส่วนตัวเป็นช่องทางเสริม หากส่งอีเมลไม่สำเร็จ ข้อมูลและการแจ้งเตือนภายในระบบต้องยังใช้งานได้ตามปกติ

## 16. ข้อจำกัดด้านสิทธิ์และการตรวจสอบย้อนหลัง

อาจารย์ไม่สามารถ:

- จัดการบทบาทบัญชีผู้ใช้
- ดูหรือแก้ไขรหัสผ่านของผู้ใช้อื่น
- ลบบัญชีผู้ใช้ถาวร
- ตั้งค่าระบบส่วนกลาง

ข้อกำหนดสำหรับการแก้ไขข้อมูล:

- การตรวจสอบสิทธิ์ต้องทำที่ฝั่งเซิร์ฟเวอร์
- ทุกการเปลี่ยนสถานะต้องเก็บผู้ดำเนินการ วันเวลา สถานะเดิม สถานะใหม่ และเหตุผลหรือหมายเหตุ
- การแก้ไขข้อมูลนักศึกษา ตารางนิเทศ และผลนิเทศต้องมี Audit Log
- การเปลี่ยนอาจารย์ผู้รับผิดชอบต้องเก็บอาจารย์เดิม อาจารย์ใหม่ และเหตุผล
- การแก้ข้อมูลที่ยืนยันแล้วต้องไม่ลบประวัติเดิม
- เอกสารและหมายเหตุภายในต้องเข้าถึงได้เฉพาะบทบาทที่ได้รับอนุญาต

| ประเมินสถานประกอบการในแต่ละรอบ | ✓ |
| จัดการบัญชีและรหัสผ่านของผู้อื่น | ✗ |
| ตั้งค่าระบบส่วนกลาง | ✗ |

## 18. ลำดับการทำงาน

```text
ดูข้อมูลการสมัครของนักศึกษา
→ ตรวจสอบหรือแก้ไขข้อมูลและสถานะ
→ ช่วยออกเอกสารเมื่อได้รับมอบหมาย
→ ส่งเอกสารแทนนักศึกษาในบางกรณี
→ ตรวจสอบและยืนยันแบบตอบรับ
→ รอการวางแผนนิเทศ
→ รับหรือแก้ไขการมอบหมายตารางนิเทศ
→ ลงพื้นที่นิเทศหรือมอบหมายอาจารย์ท่านอื่นแทน
→ บันทึกหรือแก้ไขผลการนิเทศ
→ เก็บ Requirement จากสถานประกอบการ
→ ประเมินนักศึกษาในรอบการนิเทศนั้น
→ ประเมินสถานประกอบการในรอบการนิเทศนั้น
→ ติดตามและดูผลย้อนหลัง
```
