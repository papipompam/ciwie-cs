# แผนพัฒนาระบบ CWIE สำหรับใช้งานมหาวิทยาลัย

เอกสารนี้บันทึกแผนการเปลี่ยนระบบจากข้อมูลตัวอย่าง ไปสู่ระบบที่ใช้บัญชีเข้าสู่ระบบกลางของมหาวิทยาลัยและฐานข้อมูล PostgreSQL

## เป้าหมาย

- ผู้ใช้เข้าสู่ระบบด้วยบัญชีเดียวกับ Wi‑Fi, LMS และ REG ของมหาวิทยาลัย
- ระบบไม่เก็บรหัสผ่านของผู้ใช้มหาวิทยาลัยไว้ในฐานข้อมูลของ CWIE
- ใช้ PostgreSQL เป็นฐานข้อมูลหลัก
- เริ่มทดสอบบน Cloud ได้ และสามารถย้ายตัวแอปไปเซิร์ฟเวอร์มหาวิทยาลัยภายหลังได้

## ระยะที่ 1: ทำระบบทดสอบให้ใช้งานได้

1. สร้างโปรเจกต์ PostgreSQL บน Supabase
2. เปลี่ยน Prisma และส่วนเชื่อมต่อฐานข้อมูลจาก MySQL/MariaDB เป็น PostgreSQL
3. สร้างโครงสร้างตารางใหม่บน Supabase
4. ย้ายข้อมูลตัวอย่างที่จำเป็น และตรวจสอบข้อมูลหลังย้าย
5. ตั้งค่า `DATABASE_URL` ของ Vercel ให้ชี้ไปยัง Supabase โดยเก็บเป็นค่าลับ
6. ทำให้บัญชีตัวอย่างสำหรับการทดสอบเข้าสู่ระบบได้
7. ตรวจสอบการเข้าสู่ระบบ การออกจากระบบ session และการเปลี่ยนสิทธิ์

## ระยะที่ 2: เชื่อมต่อระบบเข้าสู่ระบบของมหาวิทยาลัย

ต้องสอบถามฝ่ายไอทีมหาวิทยาลัยก่อนว่าให้เชื่อมต่อผ่านวิธีใด:

- ถ้ามีระบบ SSO แบบ OIDC หรือ SAML ให้ใช้วิธีนี้เป็นหลัก
- ถ้ามีเฉพาะระบบ LDAP ต้องมีตัวกลางที่อยู่ในเครือข่ายมหาวิทยาลัย หรือวางตัวแอปไว้ในเครือข่ายมหาวิทยาลัย

หลังยืนยันตัวตนสำเร็จ ระบบ CWIE จะบันทึกเฉพาะ:

- รหัสประจำตัวหรือรหัสอ้างอิงของผู้ใช้
- ชื่อและข้อมูลที่จำเป็นต่อการทำงาน
- สิทธิ์ เช่น เจ้าหน้าที่ อาจารย์ หรือนักศึกษา
- สถานะการใช้งานบัญชี

ระบบจะไม่บันทึกรหัสผ่าน LDAP/SSO และจะไม่ส่งรหัสผ่านไปตรวจด้วย SQL

## ระยะที่ 3: นำไปใช้จริง

1. ติดตั้งแอปบนเซิร์ฟเวอร์มหาวิทยาลัย หรือใช้ Vercel ตามนโยบายของมหาวิทยาลัย
2. เชื่อมต่อกับระบบเข้าสู่ระบบกลางผ่านช่องทางที่ฝ่ายไอทีอนุมัติ
3. กำหนดว่าจะใช้ Supabase ต่อ หรือย้าย PostgreSQL เข้าเซิร์ฟเวอร์มหาวิทยาลัย
4. ตั้งค่าเว็บไซต์ HTTPS, การสำรองข้อมูล และสิทธิ์ผู้ดูแล
5. ทดสอบกับบัญชีจริงกลุ่มเล็กก่อนเปิดใช้งานทั้งหมด

## การเข้าถึงจากภายนอกมหาวิทยาลัย

การติดตั้งแอปบนเซิร์ฟเวอร์มหาวิทยาลัยไม่ได้ทำให้ใช้งานได้เฉพาะในมหาวิทยาลัยโดยอัตโนมัติ ขึ้นอยู่กับการตั้งค่าเครือข่าย:

- จำกัดเครือข่ายหรือบังคับใช้ VPN: ใช้ได้เฉพาะในมหาวิทยาลัยหรือผ่าน VPN
- เปิดเว็บไซต์ผ่าน HTTPS และระบบป้องกันที่เหมาะสม: ผู้ใช้อาจเข้าใช้งานจากภายนอกได้

ไม่ควรเปิดระบบ LDAP ภายในมหาวิทยาลัยออกสู่อินเทอร์เน็ตโดยตรง

## สิ่งที่ต้องขอจากฝ่ายไอทีมหาวิทยาลัย

- วิธีเชื่อมต่อระบบเข้าสู่ระบบกลางที่มหาวิทยาลัยอนุมัติ
- ข้อมูลที่ระบบสามารถรับหลังผู้ใช้เข้าสู่ระบบสำเร็จ
- ข้อกำหนดว่าข้อมูลนักศึกษาต้องเก็บในประเทศหรือภายในมหาวิทยาลัยหรือไม่
- เซิร์ฟเวอร์และชื่อเว็บไซต์ที่อนุญาตให้ใช้
- ข้อกำหนดเรื่อง HTTPS, VPN, firewall, การสำรองข้อมูล และการเก็บ log
- ผู้ประสานงานเมื่อระบบเข้าสู่ระบบมีปัญหา

## สถานะปัจจุบันและเงื่อนไขก่อนเริ่มทำต่อ

- โค้ดปัจจุบันยังใช้ MySQL/MariaDB และ login ด้วยรหัสผ่านภายในระบบ
- ข้อมูลบัญชีตัวอย่างบางรายการมีเฉพาะใน mock UI และไม่ได้อยู่ในฐานข้อมูลจริง
- Vercel ยังไม่มีฐานข้อมูลที่ผูกกับโปรเจกต์ และค่า `DATABASE_URL` Production ยังใช้งานไม่ได้
- ต้องได้รับคำตอบจากฝ่ายไอทีเรื่อง OIDC/SAML หรือ LDAP ก่อนเลือกวิธีทำ login จริง
- การย้ายฐานข้อมูลและการเปลี่ยน login ต้องทดสอบบนฐานข้อมูลใหม่ก่อน ไม่ควรลบหรือรีเซ็ตฐานข้อมูลเดิม

## เกณฑ์พร้อมใช้งาน

- ผู้ใช้มหาวิทยาลัยเข้าสู่ระบบได้ด้วยบัญชีเดียวกับระบบกลาง
- ไม่มีการเก็บรหัสผ่านมหาวิทยาลัยในฐานข้อมูลหรือ log
- ระบบกำหนดสิทธิ์จากข้อมูลที่ตรวจสอบได้
- ข้อมูลใน PostgreSQL ผ่านการตรวจสอบครบถ้วน
- มีวิธีสำรองข้อมูลและกู้คืนที่ทดสอบแล้ว
- ฝ่ายไอทีมหาวิทยาลัยอนุมัติวิธีเชื่อมต่อและตำแหน่งติดตั้งระบบ
